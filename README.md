# gex-flip

从期权 GEX heatmap 的 per-strike 数据反算 **Gamma Flip**，个股 / ETF / 指数通用。
附可信度评分、瞬移风险量化、机制解读，以及一整套**诚实报告负结果**的回测。

算法在 **SPX 60 天 / 4677 帧 + 10 只标的 23 组到期上 100% 精确复现数据商的官方
`gammaFlip`，零偏差**。

## 算法

给定 heatmap 一列（一个到期日）的 `(行权价, netGex)`：

1. 按行权价升序
2. 找**相邻两档之间 netGex 符号翻转**的位置，线性插值
   `x = K低 + (K高−K低) × |netGex低| / (|netGex低| + |netGex高|)`
3. 多个零点时**取离当前现价最近的那一个**

```python
def flip(rows, spot):            # rows = [(strike, netGex), ...]
    rows = sorted(rows)
    cs = []
    for (k0, v0), (k1, v1) in zip(rows, rows[1:]):
        if v0 == 0 or v1 == 0 or v0 * v1 >= 0:
            continue
        cs.append(k0 + (k1 - k0) * (0 - v0) / (v1 - v0))
    return min(cs, key=lambda x: abs(x - spot)) if cs else None
```

### ⛔ 常见错误口径：累加和（cumsum）穿零

网上流传的「把 netGex 从低到高累加、找累加值穿零」是**错的**：

| 口径 | SPX 中位误差 | 精确复现率 |
|---|---|---|
| **单格符号翻转 + 取最近现价** | **0.00 点** | **100%** |
| 累加和穿零 | 19.16 点 | 0% |
| 从高到低累加 | 150.80 点 | 0% |
| 上下分割 `Σ下 − Σ上` | 37.23 点 | 0% |

## 原理

从做市商对冲的第一性原理往下推，一共五步。

### 1 · 做市商必须对冲 delta

客户买卖期权，对手方大多是做市商。做市商不赌方向，
成交后立刻用正股把 delta（方向敞口）对冲成零。
但对冲不是一劳永逸的——**价格每动一下，期权的 delta 就变一点，
做市商就得跟着补一手**。“delta 变化的速度”就是 gamma。

### 2 · gamma 的正负决定对冲方向，对冲方向决定行情性质

- 做市商**净 long gamma**：价格涨 → 手里 delta 自动变多 → 要**卖**出对冲；
  价格跌 → delta 变少 → 要**买**回。即**高抛低吸**——对冲单永远逆着行情打，
  波动被压平，价格容易被“钉”在大持仓行权价附近。
- 做市商**净 short gamma**：完全反过来，涨了要**追买**、跌了要**杀卖**——
  对冲单顺着行情打，波动被放大，容易出单边加速。

同样的对冲纪律，仅仅因为 gamma 符号不同，一个变成行情的减震器，一个变成助燃剂。

### 3 · GEX 把这件事变成每个行权价的一个数

GEX（Gamma Exposure，gamma 敞口）＝ 该行权价的期权 gamma × 未平仓量(OI) ×
合约乘数 × 现价，折算成“价格每动 1%，做市商要对冲多少美元”。
再套一条行业惯例假设定符号：**做市商 long call gamma、short put gamma**
（散户买 put 保护、卖 call 备兑，做市商接的是对面）——所以
`callGex 记正、putGex 记负`（本数据源实测全链零违例），

```
netGex(行权价) = callGex − |putGex|   →  这一档是 call 持仓占优还是 put 持仓占优
```

⚠️ 这条符号假设是惯例不是实测持仓，是整个 Standard GEX 口径最大的软肋。

### 4 · flip = put 主导翻成 call 主导的分界价位

put 的持仓天然堆在现价下方（保护），call 堆在上方（备兑/投机），
所以 netGex 沿行权价从下往上扫，一般会有一个**由负翻正**的位置——那就是 flip。
实测验证（6/6 成立）：

| 标的 | flip 下方 | flip 上方 |
|---|---|---|
| TSLA weekly | callOI 9,377 / putOI **107,523** | callOI **208,614** / putOI 24,344 |
| NVDA weekly | callOI 35,539 / putOI **243,367** | callOI **434,528** / putOI 53,664 |
| AAPL 1dte | callOI 3,315 / putOI **26,738** | callOI **53,969** / putOI 10,727 |

合起来：
- 现价在 flip **上方** = 做市商净 long gamma → 高抛低吸 → 抑制波动、价格易被钉住
- 现价在 flip **下方** = 做市商净 short gamma → 追涨杀跌 → 放大波动、容易加速

### 5 · 为什么算法是“单格符号 + 取最近现价”而不是累加

gamma 在行权价处最大、离开后迅速衰减 → 对“现价在 K 附近时做市商的净 gamma”，
起决定作用的就是 K 附近那几档，远处的档几乎不贡献。
所以现价附近的**单格净符号**就是最好的局部近似——这解释了本仓库逆向出的两条规则：
取**符号翻转点**而非累加和穿零（远端大仓位不该冲淡本地结构），
多个翻转点取**离现价最近**的（每个翻转点只在自己邻域内有意义）。

代价也来自同一个性质：flip 是**局部游标不是全局常量**，现价一动就可能切到
另一个翻转点上（详见下文“瞬移”）。且严格说它不是真正的零 gamma 点——
每档 gamma 是按当前现价算的，没有“假设现价移过去”重算，
所以 flip 是结构分界的**近似标记**，不是精确物理阈值。

## 个股三个坑

| | 问题 | 最差实例 |
|---|---|---|
| 1 | **分辨率粗 6-20 倍** | NVDA 一档 = 现价的 1.19%（SPX 只 0.067%）→ 别报小数点 |
| 2 | **瞬移幅度灾难级** | TSLA weekly 次近翻转点距 **31.5%** 价格（SPY/QQQ 只 0.15-0.37%）|
| 3 | **结构常常"薄"** | 厚度 <5% = 由小单撑起的噪音；过滤后翻转点消失 = 假位 |

`flip.py` 每次都会自动跑这三项检验。

## ⛔ 回测：别拿它做方向

56 天 SPX，无未来函数：

| flip 取值时点 | 上方组收涨 | 下方组收涨 | 区分度 |
|---|---|---|---|
| ① D-1 收盘帧（**盘前真正可用**） | 60% | 61% | **−1pp** |
| ② D 当天 9:30 首帧 | 71% | 48% | +23pp（1.8σ，不显著） |
| ③ D 收盘帧 vs 收盘价（⚠️未来函数） | 77% | 36% | +41pp |
| ④ D 收盘帧 vs 开盘价（⚠️未来函数） | 44% | 86% | **−42pp** |

基准收涨 60%，n=53。**盘前算的 flip 对方向零信息量**——D-1 收盘帧到次日开盘中位漂移
21.45 点。④ 出现符号翻转是典型的未来函数特征：因为 flip 的定义跟着现价跑，
「全天在 flip 上方」几乎等同于「当天涨了」，是循环论证。

入场位同样无效：触及 flip 后 30 分钟位移与随机价位无差别；盘前最大正节点当目标位，
早盘触达率 **69% vs 等距随机位 69%（+0pp）**；flip 当止损 + 2R 目标中位 **−1.00R**。

### ⭐ 唯一活下来的发现

**flip 管"波动性质"不管"方向"。**

盘前 heatmap 上开盘价 ±25 点内的翻转点个数 → 早盘趋势度（净位移 ÷ 振幅）：

| ±25 点内翻转点数 | n | 早盘振幅中位 | 早盘净位移中位 | 趋势度 |
|---|---|---|---|---|
| 0 个（结构干净） | 23 | 52.2 | 18.3 | **0.272** |
| 1-2 个 | 19 | 50.9 | 25.4 | 0.377 |
| ≥3 个（结构破碎） | 14 | 53.4 | 35.4 | **0.761** |

振幅几乎不变（52/51/53）→ 不是波动率效应，是"走不走得出方向"。
置换检验 **p = 0.001**（20000 次重排），Spearman +0.344（趋势度）vs +0.040（振幅），
前后半段稳定。**反直觉：结构越碎越走单边，越干净越磨回原地。**

⚠️ n=14/23 偏小，**只在 SPX 上测过，个股未测**。

## 数据来源

数据来自 yehangshe.com（Nightwatch / 夜航社）订阅账号的自有会话，
经 `opencli` 浏览器会话在登录态页面内 `fetch` 调用。

```
/api/gex/intraday-history?ticker=<T>&expiryGroup=1dte&bucket=5m&session=today&profile=standardGexOverlay
/api/replay-lab/day-overlays?ticker=SPX&date=YYYY-MM-DD&dealerGexSignConvention=dealer-signed-v1
```

⚠️ **口径**：以上都是 **Standard GEX**（全市场）。Dealer GEX Heatmap 是**做市商一方**，
同一行权价量级差三个数量级，两者的 flip 不是同一条线。

⚠️ **本仓库只含代码与统计结论，不含任何供应商原始数据**。`.gitignore` 已排除数据目录。
第三方数据的再分发受供应商条款约束，自己评估后再决定要不要传。

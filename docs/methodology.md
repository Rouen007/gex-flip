> 逆向自夜航社 API，SPX 60 天 / 4677 帧 + 10 只个股 23 组到期 **全部 100% 精确复现官方 `gammaFlip`，零偏差**。

## 一、算法（三步，指数个股通用）

给定 heatmap 的一列（= 一个到期日 expiryGroup）的 `(行权价, netGex)`：

1. 按行权价升序排列
2. 找**相邻两个行权价之间 netGex 符号翻转**的位置，线性插值出零点：
   ```
   x = K_low + (K_high − K_low) × |netGex_low| / (|netGex_low| + |netGex_high|)
   ```
3. 通常会有多个零点 → **取离当前现价(spot)最近的那一个** = flip

```python
def flip(rows, spot):            # rows = [(strike, netGex), ...]
    rows = sorted(rows)
    cs = []
    for (k0, v0), (k1, v1) in zip(rows, rows[1:]):
        if v0 == 0 or v1 == 0 or v0 * v1 >= 0:
            continue
        cs.append(k0 + (k1 - k0) * (0 - v0) / (v1 - v0))
    return min(cs, key=lambda x: abs(x - spot)) if cs else None
```

## ⛔ 不是累加和（cumsum）穿零

网上和我此前给的「把 netGex 从低到高累加，找累加值穿零的行权价」是**错的**。
实测（SPX 78 帧）：

| 口径 | 中位误差 | 精确复现率 |
|---|---|---|
| 单格符号翻转 + 取最近现价 | **0.00 点** | **100%** |
| 累加和穿零（cumsum） | 19.16 点 | 0% |
| 从高到低累加 | 150.80 点 | 0% |
| 上下分割 `Σ下 − Σ上` | 37.23 点 | 0% |

---

### 已知边界行为（写代码前先读）

1. **netGex 恰好为 0 的档会打断翻转检测**：`[-5, 0, +8]` 这样的序列检测不到翻转
   （相邻对里有 0 就跳过）。这与官方行为一致——60 天验证数据里含大量 0 值档，
   仍 100% 复现。但要知道：理论上这里确实有一个符号变化被跳过了。
2. **多个零点等距时取先遍历到的**（升序靠左的那个）。实测没遇到过平票。
3. **到期组能拉到什么**：`expiryGroup` 支持 `0dte / 1dte / weekly`（`monthly`、`all`
   返回 400）；一次请求会把该 ticker 当天**所有可用**到期组一起返回——个股非周五
   往往没有 0dte 组，这不是 bug。
4. **稳健检验的 5% 阈值是拍的**，不是调参调出来的。它的用途是二值报警
   （过滤后翻转点还在不在），不是精确度量。
5. 时间戳一律显示 **ET**。

## 一·五、flip 的机制（为什么这么算是对的）

**符号约定**（实测全链零违例）：`callGex` 永远 ≥0、`putGex` 永远 ≤0，
`netGex(K) = callGex(K) − |putGex(K)|` → **这一档是 call 持仓占优还是 put 持仓占优**。

背后的行业惯例假设：**做市商 long call gamma / short put gamma**（客户净买 put 做保护、
净卖 call 做备兑）。⚠️ 这是假设不是实测持仓 —— 夜航社的 Dealer GEX 就是想用成交方向
真的把做市商那一边分离出来，Standard GEX 用的还是这个惯例假设。

**所以 flip = put 持仓主导翻成 call 持仓主导的价位**。2026-08-04 实测 6/6 成立：

| 标的 | flip 下方 | flip 上方 |
|---|---|---|
| TSLA weekly | callOI 9,377 / putOI **107,523** | callOI **208,614** / putOI 24,344 |
| NVDA weekly | callOI 35,539 / putOI **243,367** | callOI **434,528** / putOI 53,664 |
| AAPL 1dte | callOI 3,315 / putOI **26,738** | callOI **53,969** / putOI 10,727 |

**为什么"单格符号"能代表制度分界**：gamma 在行权价处最大、远离迅速衰减 → 现价附近那几档
的净符号 ≈ "如果现价在这里，做市商净 gamma 的符号"。所以这是个**局部**近似，不是全局积分
—— 这正解释了为什么取「离现价最近的翻转点」而不是累加和，也解释了为什么它会瞬移。

**制度含义**：
- flip **上方** = 做市商净 long gamma → 对冲动作是**高抛低吸** → 抑制波动、价格被钉住
- flip **下方** = 做市商净 short gamma → 对冲动作是**追涨杀跌** → 放大波动、容易加速

⚠️ 严格说这不是真正的「零 gamma 点」：每档 gamma 是用**当前现价**算的，不是"假设现价
移到那里"重算 BS gamma。所以 flip 是结构分界的**近似标记**，不是精确物理阈值。

---

## 二、⚠️ 这个定义自带一个坑：flip 会瞬移

因为规则是「离**现价**最近的翻转点」，现价一动，flip 可能整个切到另一个翻转点上。

- 一帧 heatmap 上平均有 **6.5 个**符号翻转点（最多 30 个），最高最低跨度中位 **218 点**
- SPX 相邻两帧现价没怎么动（<8 点）时，flip 自己跳 >10 点的概率 = **16.6%**，跳 >30 点 = 4.4%
- SPX flip 全天极差中位 **83 点**

**所以 flip 不是一条稳定的线，是一个跟着现价走的游标。**
我试过构造「稳定 flip」（最佳分隔位，不依赖现价）反而更差（全天极差 501 点），已弃。

## 三、个股 vs 指数：两个个股独有的问题

### 问题 1 · 分辨率粗 6-20 倍

flip 只能落在相邻两档之间，档距占价格的比例决定了精度上限：

| 标的 | 档距 | 占现价 |
|---|---|---|
| SPX | 5 | 0.067% |
| SPY / QQQ | 1 | 0.13-0.14% |
| META / MSFT | 2.5 | 0.43-0.50% |
| AAPL / GOOGL / AMZN / TSLA | 2.5 | 0.66-0.90% |
| **NVDA** | 2.5 | **1.19%** |

指数上 flip 精确到 0.07%，个股上只精确到 ~1%。**在个股上给 flip 报小数点没有意义**。

### 问题 2 · 瞬移幅度是灾难级的

「次近翻转点」离当前 flip 有多远（= 现价一动 flip 会跳多少）：

| 标的 | 跳幅（占价格） |
|---|---|
| SPY / QQQ / MSFT | 0.15% – 0.37% |
| GOOGL / AMZN / META | 0.25% – 1.2% |
| SPY 1dte / IWM / TSLA 1dte | 2.2% – 2.8% |
| AAPL | 7% – 12% |
| **NVDA** | **14% – 16%** |
| **TSLA weekly** | **31.5%** |

指数上 flip 跳一下无感，**个股上 flip 一跳就是 10-30% 的价格**。所以在个股上，flip
更不能当「位」用 —— 和 [[feedback_gex_index_vs_single_stock]]（单票节点是路标不是支撑）一致。

### 问题 3 · 个股 flip 常常是「薄的」

个股期权链稀疏，翻转可能只是因为某一档挂了点小单。判断方法 ——
**厚度 = 夹住 flip 的两档中较大的 |netGex| ÷ 全链最大节点**：

- ≥20% = 厚，可信
- 5-20% = 中等
- <5% = 薄，是噪音，别当位用

2026-08-04 实测：AAPL 96.9%（厚，可信）/ META 23-26%（厚）/ TSLA 9-18%（中等）/ NVDA 12-16%（中等）。

更狠的检验：**只保留量级 ≥ 全链最大节点 5% 的行权价重算**。
当天 NVDA 的 1dte 和 weekly 过滤后**翻转点直接消失** —— 说明 NVDA 那个 flip 完全由
一档小量负 GEX 撑着，结构其实是单向的。这种情况下"NVDA 的 flip 在 202.5"是个假位。

脚本：`flip.py <TICKER>` 自动给出厚度 + 稳健 flip（原 stock_flip_quality.py 已并入）。

## 四、盘前用它做方向：⛔ 无效（56 天回测）

用 D-1 收盘那一帧（= 盘前你在 heatmap 上看到的东西）算 flip，看开盘价在它上方还是下方：

| flip 取值时点 | 上方组收涨 | 下方组收涨 | 区分度 |
|---|---|---|---|
| ① D-1 收盘帧（**盘前可用，无未来函数**） | 60% | 61% | **−1pp** |
| ② D 当天 9:30 首帧（开盘可用） | 71% | 48% | +23pp |
| ③ D 收盘帧 vs 收盘价（⚠️未来函数） | 77% | 36% | +41pp |
| ④ D 收盘帧 vs 开盘价（⚠️半未来函数） | 44% | 86% | −42pp |

基准收涨率 60%，n=53。结论：

- **盘前算出来的 flip 对方向零信息量**。原因：D-1 收盘帧算的 flip 到次日开盘中位漂移
  **21.45 点**（<5 点的只占 12%）—— 隔夜现价一动，「最近翻转点」就换人了。
- ⚠️ **`SPX_rules.md` 里那条「FLIP 位置=最强信号（上方日仅 4% 收跌 / 下方日 74% 收跌）」
  ≈ 70pp 区分度，比这里的未来函数版本 ③ 还夸张，几乎肯定是用收盘帧算的 —— 已作废。**
- ② 的 +23pp 看着能用，但 n=28/25，标准误约 13pp，只有 ~1.8σ，**没到 95% 显著**；
  且它只在**全天收盘**上出现，切到早盘 9:30-12:00 就消失（53% vs 基准 52%）。
  用户只做早盘 → **这条对用户实际无用**。

## 五、盘前用它做入场位：⛔ 也无效

- 价格触及 flip 后 30 分钟位移，与等距随机价位无差别（n 太小，7-13，但方向上随机位更好）
- 盘前最大正 gamma 节点当目标位，早盘触达率 **69%，等距随机位也是 69%，差值 +0pp**
  → 「节点是磁铁」在触达率上没有超额，只是距离效应
- flip 当止损 + 2R 目标：n=41，先止损 51% / 先到目标 32%，总 +8.2R 但**中位 −1.00R**
  （少数几笔大赢撑起来的，不是稳定盈利结构）

## 六、⭐ 唯一活下来的发现：翻转点密度 → 早盘趋势度

盘前 heatmap 上，**开盘价 ±25 点范围内有几个符号翻转点**，预测当天早盘是走单边还是来回磨：

| ±25 点内翻转点数 | n | 早盘振幅中位 | 早盘净位移中位 | **趋势度**（净位移/振幅） |
|---|---|---|---|---|
| 0 个（结构干净） | 23 | 52.2 | 18.3 | **0.272** |
| 1-2 个 | 19 | 50.9 | 25.4 | 0.377 |
| ≥3 个（结构破碎） | 14 | 53.4 | 35.4 | **0.761** |

- **振幅几乎不变（52/51/53），变的是净位移** → 这不是波动率效应，是「走不走得出方向」
- 置换检验 p = **0.001**（20000 次重排）
- Spearman 相关 +0.344（对趋势度）vs +0.040（对振幅）—— 干净地只挂在趋势度上
- 前后半段稳定：0 个组 0.349 → 0.373，≥3 个组 0.672 → 0.687

**方向和直觉相反**：翻转点越碎 = 走势越单边；结构越干净 = 越容易磨回原地。

⚠️ 限制：n=14/23 偏小；只在 SPX 上测过（**个股上没测**，个股翻转点本来就少，
±25 点这个绝对阈值也要改成百分比）；这是**日型判断**，不是入场信号，不给方向。

## 七、数据接口

```bash
# 个股 / ETF 实时（expiryGroup 就是 heatmap 的到期日列）
/api/gex/intraday-history?ticker=TSLA&expiryGroup=1dte&bucket=5m&session=today&profile=standardGexOverlay
  → data.latestPayload.expiryGroups[<组名>].strikes[]  每档带 {strike, netGex, callGex, putGex, callOi, putOi}
  → data.latestPayload.expiryGroups[<组名>].summary.gammaFlip  官方值，用来对答案
  expiryGroup 可选 0dte / 1dte / weekly（monthly 和 all 返回 400）
  ⚠️ 一次请求会把该 ticker 所有可用到期组一起返回，不用逐个拉

# SPX 历史回放（90 天滚动）
/api/replay-lab/day-overlays?ticker=SPX&date=YYYY-MM-DD&dealerGexSignConvention=dealer-signed-v1
  → data.standardGexFrames[].strikes[]  （harvest_api.sh 原来把这个丢了，
     现在 harvest_strikes.sh 专门采它，存 strikes/st_DATE.json）
```

⚠️ 口径：以上都是 **Standard GEX**（全市场）。Dealer GEX Heatmap 是**做市商一方**，
同一行权价量级差三个数量级，两者的 flip 不是同一条线，别互相验证。

## 八、一句话结论

**算法本身 100% 可复现，指数个股通用；但算出来的 flip 在盘前对方向和入场都没有可交易的
edge。它是张地图上的标记，不是信号。** 个股上还要额外扛分辨率粗、瞬移大、结构薄三个问题 ——
在个股上用之前先跑 `flip.py` 看厚度，薄的直接扔。
